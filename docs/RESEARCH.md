# Reference inspection — 2026-11-08

Read source before implementation: [Charades Wheel.lua](https://github.com/damesene/wow-charades/blob/main/Wheel.lua), [Actions.lua](https://github.com/damesene/wow-charades/blob/main/Actions.lua), [Editor.lua](https://github.com/damesene/wow-charades/blob/main/Editor.lua), [Charades_Camelot.toc](https://github.com/damesene/wow-charades/blob/main/Charades_Camelot.toc), [CurseForge listing](https://www.curseforge.com/wow/addons/charades), and [Forever Addon Kit](https://github.com/Thunderz96/forever-addon-kit).

Observed in source:

- Charades ships a `_Camelot.toc` declaring interface `16001`; ship a matching In Character flavor TOC plus the ordinary TOC. No evidence for a `_Forever.toc` convention in these references.
- Wheel input comes from binding down/up callbacks, cursor coordinates divided by effective scale, and direct mouse handlers. Escape uses `UISpecialFrames`. Its hover opens inner categories and outer selection runs on key release. In Character uses independently written, explicitly entered submenus and resets hover between pages to reduce accidental selection.
- Actions.lua enumerates `EMOTE<n>_TOKEN` and localized `CMD1..4` globals, calls `DoEmote`, and prefers `C_ChatInfo.SendChatMessage` with global fallback. In Character only dispatches recognized emotes and pool text. No arbitrary slash, sequence, macro, protected-action, or timer execution is included.
- Editor uses `BackdropTemplate`, `InputBoxTemplate`, and explicit combat guards. In Character uses its own compact standalone editor.
- The kit measures a modern API with interface 16001, notes unknown-event registration errors, and documents beta-era secure-snippet and SavedVariables bugs. These are historical observations, **not proof of current live-client behavior**. In Character feature-detects relevant APIs, guards event registration, uses no secure snippets, and requires live persistence checks. It does not install external bridges or write macros as a workaround.

Code and UI assets are independently written; Charades is a behavioral/API reference. The curated animation metadata added in 0.3.1 is drawn from its Defaults.lua command list/category declarations, with the existing MIT notice retained. No Charades icons or arbitrary command execution were imported.

## Audit follow-up, 0.3.1

- [Forever bug #34](https://github.com/ClassicWoWCommunity/forever-bugs/issues/34) was checked directly: the reporter marked SavedVariables loading fixed in build 70009 on 2026-09-24. The kit's older row is not evidence that live persistence remains broken. This addon still needs a reload/full-restart integration test.
- Shipped modern [ChatInfo API documentation](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/ChatInfoDocumentation.lua) defines InChatMessagingLockdown, restricted SendChatMessage and PerformEmote with a success boolean. [RestrictedActions documentation](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/RestrictedActionsDocumentation.lua) defines the addon restriction predicate, and [SocialRestrictions documentation](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/SocialRestrictionsDocumentation.lua) defines CanSendChat. These are primary modern API references, not a live Forever execution test. The addon feature-detects each API and checks permissions before selection; it never infers lockdown just from being inside an instance.
- Modern PerformEmote is preferred; a refusal is not retried through DoEmote. Legacy fallback/result behavior still belongs on the live checklist.
- The original kit research established the client family/interface and reported compatibility hazards. Chat widgets, key callbacks and frame patterns were inspected in **Charades source**; they were not established by the kit README alone. No complete fresh API-surface scan is claimed in this implementation session.
- `_forever_` was supplied in SPEC.md; the inspected `_Camelot.toc` evidence comes from Charades. The ordinary interface-16001 TOC remains available as a fallback. No unverified `_Forever.toc` convention is assumed here.
